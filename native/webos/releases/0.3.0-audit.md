# Release audit — OTTPlay Native 0.3.0

This is the authored preparation record for the planned `native-webos-v0.3.0-beta.1` release. No final release package, source export or publication receipt was supplied for this draft. The reserved artifact-evidence section is deliberately unfilled. This document does not qualify a package or authorize a compatibility claim.

## Device test evidence

No physical-LG installation, protected-storage, video/audio playback, seek, end-of-file continuation or offline-restart result was supplied for this candidate. No device was accessed for this documentation task.

Source inspection establishes implementation paths, not successful playback. A Mac host test or simulator result must retain its own exact source and executable identity; it cannot establish ARM loader compatibility, LG filesystem permissions, hardware decoding or a working Homebrew installation. Older candidate results must not be relabeled as this release's evidence.

Earlier focused host evidence records passing core groups and Torrent tests at source `5fabf45e400de78e5e69cabf819d95ef664ee7fe`, and passing Stremio tests at `73617a679dbdb6631681a4901f2be0cf710a4bf4`. These receipts do not attest the later source snapshot. The normal non-test host build at `06495b320434273727e9b7f5fd6a2227d6fb9cfe` failed before producing an accepted candidate. No final ARM or physical-device verdict follows from any of these host results.

A later scoped Mac run used source `0751131eee8c0a2a358d3bab6fc669a11765e749`
and executable SHA-256 `1a898121d0c5ee22f927c9043dacde2182b7e060419158847b7e85ac1a710fec`.
It exercised normal pairing, both interface presentations, moving Local video,
catalogue/player round trips and transitions between two distinct Local files.
The process then exited with SIGABRT after the third EOF, with the watchdog
reporting a main-thread stall. Sustained playback stability therefore **failed**.
Graceful product Exit and offline restart were **not tested**; the ClockSink
audio backend did not establish audible audio. Mode changes were made with
playback stopped, so this run does not prove uninterrupted mode switching.

The same run's ordinary Plex fixture filled its catalogue but failed playback:
the client requested conversion and the fixture, which has no transcoder,
returned 4007; rapid failed-item advancement followed. Repair patches and
isolated tests do not replace a successful repeat of that native run. Neither
these limited observations nor the failures qualify source `bfa8b52` or the
eventual ARM release package.

## Source scope reviewed

The user-guide revision was checked against native integration source `bfa8b52be91b4b3651ae1fe644630a71de8fde23`. This is a source reference, not the identity of a newly qualified release package. The final crash/Plex integration and publication build must receive their own evidence.

Classic and Modern share the source/profile model and a saved interface-mode setting. M3U, Xtream, Stalker, VPortal and Plex catalog paths, Local and Server library adapters, categories, portable Favorites and native remote settings are present. The media-attachment setting is provider-scoped and uses runtime, context and revision checks. Favorites retain source identity; a receiving player still needs a matching configured source and local access.

Local folder discovery reads source files rather than importing their media bytes. Verified drive identity can assist rebinding, but does not mount a drive or grant access. Server library remains network-dependent. Torrent uses an optional local companion and a bounded cache; its capability response controls availability. Catalog and stream manifests are separate from remote-control and indexer endpoints.

These observations are source findings. They are not a claim of complete Classic parity, of a final packaged companion, or of successful playback on a particular television.

## Known issues at release, with provenance

- **Classic and Modern are implemented, with qualification still required.** The current candidate has both presentations and a writable `interfaceMode` setting. Earlier Mac screenshots demonstrate their appearance at their own source/binary identity; they do not prove all actions, saved-state behavior or physical-LG compatibility in the final package.
- **Global settings Export/Import is pending.** The supplied transfer contract is a proposal. Its Classic codec and native declaration/fixture checks do not implement or exercise a native importer, transport, persistence transaction or user interface.
- **An attached-media Favorite can be pinned as one kiosk item.** The pin is bound to its exact M3U parent profile and attachment; replay revalidates that binding and the parent authorization. Mixed attached-media kiosk queues are not supported. This source behavior does not establish physical-LG acceptance.
- **Expanded USB folder selection and restoration are proposed.** The separate USB source packet adds a nested folder picker and verified folder-kiosk restoration. Its 49 written tests were not compiled or run for that packet; earlier narrower USB tests do not qualify it. No physical-LG USB access, disconnected-network playback, drive reattachment or cold-start result is supplied. The application must verify its own folder access; a shell-visible mount is insufficient.
- **Final qualification remains open.** Source and partial host checks do not close the normal-Mac candidate, full regression, ARM package, source-closure or physical-LG acceptance requirements. The source must be frozen again after outstanding fixes before results can be attached to a release.
